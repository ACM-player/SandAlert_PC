## 1. 系统整体架构与业务流

### 1.1 系统概述

SandAlert PC 是一套面向油气管道多相流环境的**含砂量在线监测系统**的上位机软件。系统通过压电陶瓷声学传感器（Acoustic Emission Sensor）贴附于管道外壁，实时采集砂粒撞击管壁产生的声发射信号，经由下位机 STM32 微控制器进行初步采样与编码后，通过 CH340 串口（UART）上传至上位机 PC。上位机运行基于 PySide6 的 Qt 图形界面，在后台利用 **QThread 多线程架构**实现数据采集与信号处理的解耦，最终在用户界面呈现实时波形、瞬时出砂量（Mass Rate）、撞击率（Impact Per Second, IPS）、三相分离器分离效率，以及历史累积出砂趋势。

### 1.2 数据流全景

整个系统的数据流向可概括为以下链路：

```
[压电传感器] → [STM32 采样 (1000 Hz)] → [CH340 串口]
    ↓
[SerialReaderThread]  ←  真实串口模式（硬件 / 虚拟串口）
[FileReplayThread]    ←  文件回放模式（本地 .txt 文件）
    ↓  (Signal: data_received, 统一接口)
[DSPEngine.process_window()]  ←  核心数字信号处理
    ↓  (滤波 → 整流 → 寻峰 → 能量计算)
[SignalTracesTab.update_from_serial()]  ←  UI 实时更新
    ↓
[实时模式: 波形图 + IPS + Mass Rate + 分离效率 + CSV 录制]
[历史模式: DataLogWidget 累积趋势图]
```

#### 1.2.1 双模式架构

系统通过 `QStackedWidget` 实现两种工作模式的切换（由菜单栏 `Operation` 控制）：

| 模式 | 索引 | 功能描述 |
|------|------|----------|
| **SandAlert PC (实时监测)** | 0 | 包含 `Signal Traces`（实时波形、效率评估、CSV 录制）与 `Parameters`（参数设置）两个子页签，用于在线监测瞬时出砂动态 |
| **DataLogging (历史日志)** | 1 | 加载历史 `.txt` 数据文件夹，利用同一 DSP 引擎批量解析，绘制累积出砂量宏观趋势图 |

#### 1.2.2 多线程解耦设计

由于声学传感器采样率高达 **1000 Hz**，若将串口读取、信号处理与 UI 渲染全部置于同一线程，将不可避免地导致界面卡顿。为此，系统采用以下多线程架构：

- **通信线程（`SerialReaderThread` / `FileReplayThread`）**：  
  在独立的后台线程中持续从串口（或本地文件）读取原始电压数据，每积攒 **50 个采样点**（`chunk_size = 50`）即通过 Qt 信号 `data_received` 发射至主线程。此设计将 I/O 阻塞与 UI 事件循环完全隔离。

- **主线程（UI 线程）**：  
  接收数据后，调用 `DSPEngine.process_window()` 执行完整的数字信号处理流水线，随后更新 PyQtGraph 波形图、顶部数字标签、三相分离器效率进度条，以及 CSV 工业报表的实时写入。由于 DSP 计算量较小（单次窗口处理在微秒级），在主线程中同步执行不会造成界面感知上的延迟。

> **关键设计：** `SerialReaderThread` 和 `FileReplayThread` 的 `data_received` 信号格式完全一致（均发射 `numpy.ndarray`），因此 UI 层无需关心数据来源，只需绑定 `update_from_serial` 槽函数即可。这一抽象使得系统可以在真实硬件、虚拟串口、文件回放三种数据源之间无缝切换。

## 2. 核心信号处理算法 (DSP Pipeline)

`DSPEngine` 是整个系统的算法核心，封装于 `core/dsp_engine.py`。其信号处理流水线（Pipeline）包含以下四个关键阶段：

```
原始电压信号 → ① 高通滤波 → ② 信号整流 → ③ 动态阈值计算 → ④ 寻峰与能量提取
```

### 2.1 四阶巴特沃斯高通滤波器

#### 2.1.1 滤波器设计参数

```python
self.fs = 1000                     # 采样率 1000 Hz
self.nyq = 0.5 * self.fs = 500    # 奈奎斯特频率
cutoff_freq = 20.0                 # 截止频率 20 Hz
normal_cutoff = 20.0 / 500 = 0.04 # 归一化截止频率
self.b, self.a = butter(4, 0.04, btype='high', analog=False)
```

滤波器类型：**4 阶巴特沃斯高通滤波器**（Butterworth High-Pass Filter）  
截止频率：**20 Hz**  
采样率：**1000 Hz**

#### 2.1.2 物理原理与设计动机

**（1）消除 -2.85V 固有直流偏置（DC Offset）**

现场压电传感器在无砂粒撞击的静默状态下，输出信号存在约 **-2.85 V** 的恒定直流偏置。该偏置来源于传感器前置放大电路的参考电位设定。若不对其进行处理，后续的阈值比较与寻峰算法将完全失效——因为所有信号都叠加在一个非零的基线上。

高通滤波器的传递函数为：

$$H(s) = \frac{s^n}{\prod_{k=1}^{n} (s - p_k)}$$

其中 $n = 4$ 为滤波器阶数，$p_k$ 为巴特沃斯极点。对于直流分量（$f = 0$ Hz），$H(0) = 0$，因此滤波器能够**完全抑制直流分量**，使输出信号的基线完美归零。这一特性由 `scipy.signal.filtfilt` 的零相位滤波实现——它通过对信号进行正向和反向两次滤波，消除了普通滤波器（如 `lfilter`）引入的相位失真，确保滤波后的波形在时间轴上与原始信号对齐。

**（2）抑制低频水流湍流干扰**

在油气管道多相流环境中，水流、气流等流体运动会产生大量的低频机械振动（通常在 **0.5 – 15 Hz** 频段）。这些振动通过管壁传导至压电传感器，形成强烈的背景噪声。相比之下，砂粒撞击管壁产生的声发射信号具有**宽频带特性**，其能量主要集中在 **20 Hz 以上**的高频区域。

将高通滤波器的截止频率设定为 **20 Hz**，可在保留有效砂粒撞击信号的同时，最大限度地衰减水流湍流等低频干扰。这一参数选择基于现场实验的反复验证，是信号预处理环节的关键设计决策。

**（3）巴特沃斯滤波器的优势**

巴特沃斯滤波器以其**通带内最大平坦**的频率响应特性著称。对于声发射信号处理而言，这一特性尤为重要——它保证了在通带（> 20 Hz）内不同频率成分的幅值衰减一致性，避免了因滤波器幅频响应起伏导致的信号畸变，从而为后续的定量能量计算提供了保真度保障。

### 2.2 信号整流（Rectification）

```python
rectified_signal = np.abs(filtered_signal)
```

高通滤波后的信号基线已归零，砂粒撞击表现为正负交替的衰减振荡波形。取绝对值（全波整流）将所有负向波峰翻转为正向，使得后续的 `find_peaks` 寻峰算法能够统一检测所有方向的撞击能量，而无需区分波峰的正负极性。

从数学角度，整流操作等价于计算信号的**瞬时幅值包络**的近似：

$$x_{\text{rect}}(t) = |x_{\text{filtered}}(t)|$$

### 2.3 本底与动态阈值

#### 2.3.1 本底噪声（Background Level）

```python
sb = np.mean(rectified_signal)
```

整流后的信号本底 $s_b$ 定义为当前分析窗口内整流信号的平均值：

$$s_b = \frac{1}{N} \sum_{i=1}^{N} |x_f[i]|$$

其中 $N$ 为窗口长度（当前为 3000 个采样点，对应 3 秒数据），$x_f[i]$ 为滤波后的信号序列。

**物理意义：** $s_b$ 表征了当前时间窗口内的**平均背景噪声水平**。在无砂粒撞击时，整流信号主要由传感器电子噪声和残余流体湍流噪声构成，$s_b$ 反映这一本底能量的统计均值。

#### 2.3.2 动态阈值（Dynamic Threshold）

```python
dynamic_threshold = sb + threshold_margin
```

其中 `threshold_margin` 为用户可调的阈值裕量（系统默认值为 **0.008 V**，即 8 mV）。

**物理意义：** 动态阈值 $T_{\text{dyn}}$ 是本底噪声与固定裕量之和：

$$T_{\text{dyn}} = s_b + \Delta V$$

这一设计的精妙之处在于其**自适应性**：当管道内流体噪声水平发生变化时（例如流速增大导致背景噪声升高），$s_b$ 随之增大，阈值自动上移，从而有效避免因背景噪声波动导致的误触发；反之，当环境安静时，阈值自动降低，保持对微弱砂粒信号的高灵敏度。

0.008 V 的裕量值经现场反复标定验证，是在**灵敏度**与**抗误报**之间取得的最佳平衡点。

## 3. 防翻车与抗干扰机制

### 3.1 问题背景：传感器插拔脉冲

在实际工业现场，传感器线缆的插拔、电磁干扰（EMI）的瞬态冲击、以及静电放电（ESD）等事件，会在信号线上产生**幅值极大的瞬态脉冲**（可达 ±5 V 甚至更高）。若不对这些异常脉冲加以处理，它们将被误判为砂粒撞击信号，导致出砂量计算严重偏离真实值。

### 3.2 关键设计决策：滤波前禁止截断

系统设计文档中有一条明确的工程约束：

> **绝对不能**在滤波前对原始信号执行 `np.clip()` 电压截断操作。

#### 3.2.1 为什么不能在滤波前做截断？

考虑一个幅值为 +5 V、持续时间为 1 ms 的插拔脉冲叠加在 -2.85 V 的直流偏置上。若在滤波前将其截断至合理范围（例如 ±2.0 V），截断后的信号波形将呈现为**平顶的削波波形**。

高通滤波器对**阶跃信号**和**平顶信号**的响应存在严重的**振铃效应（Ringing Effect）**。具体而言：

1. 巴特沃斯高通滤波器的单位阶跃响应 $h(t)$ 存在过冲（Overshoot）和振铃。对于 4 阶系统，其阶跃响应的过冲量可达 **10% – 15%**，且振铃持续时间与滤波器阶数成正比。
2. 被截断的平顶信号在滤波器看来是一个**持续时间较长的近似阶跃**，其输出将产生持续数十毫秒的衰减振荡。
3. 这一振铃信号的幅值可能远超正常的砂粒撞击信号，导致后续寻峰阶段产生**大量假波峰**，且这些假波峰在时间上高度聚集，严重污染能量计算。

数学上，设截断后的信号为 $x_c(t)$，其与原始信号 $x(t)$ 的关系为：

$$x_c(t) = \begin{cases} V_{\text{clip}}, & x(t) > V_{\text{clip}} \\ x(t), & |x(t)| \leq V_{\text{clip}} \\ -V_{\text{clip}}, & x(t) < -V_{\text{clip}} \end{cases}$$

截断操作引入了**非线性畸变**，使得 $x_c(t)$ 在截断点处产生一阶导数不连续。高通滤波器对这类不连续点的响应表现为：

$$y(t) = \int_{0}^{t} h(t-\tau) x_c(\tau) d\tau$$

由于 $x_c(\tau)$ 在截断区间内为常数，其导数为零，但边界处的跳变导数趋于无穷，导致 $y(t)$ 产生大幅振铃。

#### 3.2.2 正确的处理策略

系统的正确做法是：

1. **原始信号直接送入高通滤波器**：利用滤波器自身的直流抑制能力，将 -2.85 V 偏置归零，同时保留脉冲信号的原始形态。
2. **在寻峰阶段剔除异常波峰**：滤波归零后，正常砂粒撞击的整流幅值通常在 **0.01 – 1.5 V** 范围内。系统设定 `PEAK_AMPLITUDE_LIMIT = 2.0 V`，在 `find_peaks` 找到所有候选波峰后，通过列表推导式剔除幅值超过 2.0 V 的异常波峰：

```python
valid_peaks = [p for p in peaks if rectified_signal[p] < self.PEAK_AMPLITUDE_LIMIT]
```

此时基线已在 0 V 附近，任何幅值超过 2.0 V 的波峰必然是传感器插拔等硬件异常产生的极端脉冲，而非真实的砂粒撞击信号。

### 3.3 抗干扰机制总结

| 干扰类型 | 抑制手段 | 原理 |
|----------|----------|------|
| -2.85 V 直流偏置 | 高通滤波器 (20 Hz) | $H(0) = 0$，直流分量被完全抑制 |
| 低频水流湍流 (0.5–15 Hz) | 高通滤波器 (20 Hz) | 截止频率以下信号衰减 > 24 dB/oct |
| 传感器插拔脉冲 (>2.0 V) | 寻峰后幅值限幅 | 基线归零后，>2.0 V 必为异常 |
| 背景噪声波动 | 动态阈值 $s_b + \Delta V$ | 阈值随本底自适应调整 |

## 4. 声学能量提取与物理标定模型

### 4.1 波峰提取与纯声学能量计算

#### 4.1.1 寻峰算法

系统使用 SciPy 的 `find_peaks` 函数在整流后的信号中定位砂粒撞击事件：

```python
peaks, peak_properties = find_peaks(rectified_signal, height=dynamic_threshold, distance=10)
```

参数说明：
- `height=dynamic_threshold`：仅保留幅值高于动态阈值的波峰，过滤背景噪声。
- `distance=10`：两个相邻波峰之间至少间隔 10 个采样点（即 10 ms），防止同一撞击事件的多次振荡被重复计数。

#### 4.1.2 纯声学能量公式

对于每个有效波峰，系统提取其峰值幅值 $s_p$，并计算该波峰相对于本底 $s_b$ 的**超额能量**：

$$E = \sum_{i=1}^{N_{\text{peaks}}} (s_{p,i} - s_b)^2$$

其中：
- $s_{p,i}$：第 $i$ 个有效波峰的整流幅值（单位：V）
- $s_b$：当前窗口的整流信号本底均值（单位：V）
- $N_{\text{peaks}}$：当前窗口内的有效波峰数量

**物理意义：**

该公式的物理基础建立在**声发射信号的能量与砂粒动能之间的正相关性**之上。当砂粒以速度 $v$ 撞击管壁时，其动能 $E_k = \frac{1}{2} m v^2$ 的一部分转化为声能向外辐射。压电传感器将声压波动转换为电压信号 $V(t)$，而电压信号的平方 $V^2(t)$ 正比于瞬时声功率。

$(s_p - s_b)^2$ 表示扣除本底噪声后的**净声学能量贡献**。求和操作将所有波峰的能量贡献累加，得到当前时间窗口内的总声学能量 $E$。

> **注：** 系统使用波峰幅值而非完整波形积分来计算能量，这是一种工程近似。其隐含假设是：每个砂粒撞击产生的声发射波形具有相似的形态（即相似的衰减振荡包络），因此波峰幅值的平方可以代表该撞击事件的相对能量。这一近似在工程实践中被证明是有效的。

### 4.2 标定（Calibration）的底层逻辑

#### 4.2.1 为什么需要标定？

声学能量 $E$ 与砂粒质量 $m$ 之间的关系并非固定不变，而是受到以下因素的强烈影响：

1. **管道几何与材料**：管壁厚度、材质（碳钢/不锈钢）、曲率半径等影响声波的传播与衰减。
2. **传感器耦合条件**：传感器与管壁之间的耦合剂、压紧力、接触面积等影响声电转换效率。
3. **流体介质与流速**：管道内的介质（油/气/水混合比）和流速影响砂粒的撞击速度 $v$。
4. **传感器灵敏度**：不同传感器的压电系数存在差异。

因此，**必须通过现场标定实验**来确定特定工况下的转换系数，才能将声学能量可靠地映射为物理质量。

#### 4.2.2 标定流程

标定过程由用户在 `Parameters` → `Calibration` 页签中操作，其核心逻辑如下：

```
Step 1: 用户输入已知注砂量 Injected Mass [g]（例如 100 g）
Step 2: 点击 "Start Calibration Accumulation"
Step 3: 系统清空能量累加器，进入累加模式
Step 4: 用户向管道中注入已知质量的砂
Step 5: 系统实时累加每个 DSP 窗口的纯声学能量 E
Step 6: 点击 "Stop & Calculate Factor"
Step 7: 系统计算转换系数 Factor = Total Energy / Injected Mass
```

#### 4.2.3 转换系数的推导

设标定过程中系统累加的总声学能量为 $E_{\text{total}}$，用户注入的已知砂质量为 $M_{\text{injected}}$，则转换系数 $K_{v^2}$ 定义为：

$$K_{v^2} = \frac{E_{\text{total}}}{M_{\text{injected}}}$$

其量纲为 $\text{V}^2/\text{g}$（伏特平方每克）。

**推导过程：**

假设每个砂粒撞击产生的声学能量 $E_i$ 与该砂粒的质量 $m_i$ 和撞击速度 $v_i$ 的平方成正比：

$$E_i = k \cdot m_i \cdot v_i^2$$

其中 $k$ 为综合比例常数（包含声电转换效率、声波传播衰减等）。对所有砂粒求和：

$$E_{\text{total}} = \sum_i E_i = k \sum_i m_i v_i^2$$

在标定实验中，假设所有砂粒的撞击速度近似相等（$v_i \approx v$），则：

$$E_{\text{total}} = k v^2 \sum_i m_i = k v^2 \cdot M_{\text{injected}}$$

因此：

$$K_{v^2} = \frac{E_{\text{total}}}{M_{\text{injected}}} = k v^2$$

$K_{v^2}$ 本质上是一个**集总参数**，它隐含包含了传感器灵敏度、管道声学特性、以及砂粒平均撞击速度等所有未知因素的综合影响。

### 4.3 瞬时出砂量的实时反推

标定完成后，系统进入正常监测模式。对于每个 DSP 窗口，实时瞬时出砂量（Mass Rate）的计算公式为：

$$M_{\text{rate}} = \frac{E_{\text{window}}}{K_{v^2}}$$

其中 $E_{\text{window}}$ 为当前窗口的纯声学能量（由 4.1.2 节公式计算）。

**代码实现：**

```python
# 计算纯声学能量
window_energy = np.sum((sp - sb)**2)

# 反推出砂量
mass_rate = window_energy / k_v2
```

**物理意义：**

该公式是标定过程的逆运算。标定确定了"单位质量砂粒产生多少声学能量"（$K_{v^2}$），实时监测则利用这一关系，从实测声学能量反推出"产生这些能量需要多少质量的砂粒"。

由于 $K_{v^2}$ 是在特定工况下标定得到的，它隐含了该工况下的所有系统参数。当工况发生显著变化时（例如管道流速大幅改变），需要重新标定以获得新的转换系数。

### 4.4 撞击率（IPS）与报警机制

#### 4.4.1 撞击率

撞击率（Impacts Per Second, IPS）定义为每个 DSP 窗口内检测到的有效波峰数量：

$$\text{IPS} = N_{\text{valid\_peaks}}$$

它反映了单位时间内的砂粒撞击频次，是评估出砂严重程度的辅助指标。

#### 4.4.2 三级报警状态机

系统基于瞬时出砂量 $M_{\text{rate}}$ 实现三级报警：

| 状态 | 条件 | 指示灯颜色 | 继电器动作 |
|------|------|------------|------------|
| **NORMAL** | $M_{\text{rate}} < 0.05$ g/s | 绿色 | 无动作 |
| **CAUTION** | $0.05 \leq M_{\text{rate}} < 0.10$ g/s | 黄色 | 触发继电器 1 |
| **CRITICAL ALARM** | $M_{\text{rate}} \geq 0.10$ g/s | 红色 | 触发继电器 2 |

报警阈值（0.05 g/s 和 0.10 g/s）可通过 `Parameters` → `Relays` 页签由用户根据现场工况灵活调整。

## 5. 三相分离器效率评估模型

### 5.1 工程背景

在油气开采过程中，三相分离器（Three-Phase Separator）是用于将采出液分离为油、气、水三相的关键设备。砂粒作为固体杂质，其携带量直接反映分离器的分离性能。若分离器效率下降，将导致过量砂粒进入下游管线，造成设备磨损和管道堵塞。

SandAlert PC 系统利用实时监测到的瞬时出砂量 $M_{\text{rate}}$，结合用户输入的流体流量 $Q_{\text{fluid}}$，在线评估三相分离器的分离效率。

### 5.2 效率计算公式

效率评估模型位于 `SignalTracesTab.update_from_serial()` 方法中，其核心计算公式为：

$$\eta = \frac{M_{\text{rate}} / 1000}{Q_{\text{fluid}}} \times 100\%$$

其中：
- $\eta$：三相分离器分离效率（百分比，范围 0% – 100%）
- $M_{\text{rate}}$：瞬时出砂量（单位：g/s），由 DSP 引擎实时计算
- $Q_{\text{fluid}}$：用户输入的流体流量（单位：kg/s），默认值为 10.0 kg/s

**量纲分析：**

$$\eta = \frac{[\text{g/s}] / 1000}{[\text{kg/s}]} \times 100\% = \frac{[\text{kg/s}]}{[\text{kg/s}]} \times 100\%$$

分子将 $M_{\text{rate}}$ 从克/秒（g/s）换算为千克/秒（kg/s），与分母的流体流量单位一致，确保比值无量纲。

### 5.3 物理意义

该效率指标本质上表征了**单位质量流体中所夹带的砂粒质量占比**。在理想情况下，高效分离器应使绝大部分砂粒被分离出来，出砂量极低，效率趋近于 0%。当分离器性能下降时，出砂量升高，效率值增大。

> **注：** 此处的"效率"定义与常规分离效率（被分离砂量/总砂量）有所不同。本系统定义的 $\eta$ 更准确地应称为**出砂浓度指数**，其数值越低表示分离效果越好。在实际工程应用中，操作人员通过监测该指标的突变来预警分离器故障。

### 5.4 UI 呈现

效率值通过一个蓝色进度条（`QProgressBar`）实时呈现，范围限定在 0 – 100 之间，并保留 4 位小数显示：

```python
efficiency = np.clip(efficiency, 0.0, 100.0)
self.efficiency_bar.setValue(int(round(efficiency)))
self.efficiency_bar.setFormat(f"Efficiency: {efficiency:.4f}%")
```

高精度小数显示（4 位）旨在体现精密仪器的测量分辨率，即使极微小的出砂量变化也能在效率值上得到反映。

### 6.1 功能概述

```
    ↓

    ↓

```

### 6.3 CSV 数据格式

CSV 文件包含以下 6 列数据字段：

| 列名 | 数据类型 | 单位 | 描述 |
|------|----------|------|------|
| `Timestamp` | 字符串 | — | 时间戳，精确到毫秒（格式：`YYYY-MM-DD HH:mm:ss.SSS`） |
| `IPS` | 整数 | /s | 每秒撞击次数 |
| `MassRate(g/s)` | 浮点数 | g/s | 瞬时出砂率，保留 5 位小数 |
| `Efficiency(%)` | 浮点数 | % | 三相分离器效率，保留 2 位小数 |
| `Current(mA)` | 浮点数 | mA | 模拟 4-20 mA 工业电流信号 |
| `CumulativeMass(g)` | 浮点数 | g | 本次录制期间的累积出砂量，保留 4 位小数 |

### 6.4 模拟 4-20 mA 工业电流信号

为兼容工业 SCADA 系统的标准接口，系统在 CSV 中额外记录了一路模拟的 **4-20 mA 电流信号**：

$$I_{\text{mock}} = 4.0 + M_{\text{rate}} \times 0.1$$

其中 4.0 mA 为底值（对应零出砂状态），$M_{\text{rate}}$ 越大电流值越高。这一设计使得 SandAlert PC 的数据格式与工业标准 4-20 mA 变送器输出兼容，便于接入现有的 DCS（分布式控制系统）或 PLC（可编程逻辑控制器）系统。

### 6.5 累积出砂量追踪

系统在每次录制会话中维护一个累加器 `total_mass_recorded`，其更新逻辑为：

```python
dt = shift / 1000.0  # 本次数据块的时间间隔（秒）
step_mass = mass_rate * dt  # 本次数据块产生的出砂质量（克）
self.total_mass_recorded += step_mass
```

其中 `shift` 为本次接收的数据点数（通常为 50），`dt` 为对应的时间跨度。通过积分瞬时出砂率，得到录制期间的累积出砂总量。

## 7. 双模通信架构与虚拟串口硬件模拟器

### 7.1 双模数据源架构

系统支持两种数据源模式，通过 `SetupDialog` 通信设置对话框进行选择：

```
┌──────────────────────────────────────────────────┐
```

#### 7.1.1 串口模式（Serial Port Mode）

当选择串口模式时，系统使用 `SerialReaderThread` 从真实的 CH340 串口（或虚拟串口）读取数据。该线程：

1. 使用 `pyserial` 库打开指定串口（如 `/dev/tty.usbserial-1410`）。
2. 按行读取数据（每行一个浮点数电压值，以换行符 `\n` 分隔）。
3. 每积攒 50 个数据点，打包为 `numpy.ndarray` 并通过 Qt 信号发射至主线程。

```python
# SerialReaderThread 核心读取逻辑
raw_line = self.serial_port.readline()
decoded = raw_line.decode('utf-8', errors='ignore').strip()
if decoded:
    voltage_val = float(decoded)
    self.buffer.append(voltage_val)
    if len(self.buffer) >= self.chunk_size:
        np_data = np.array(self.buffer, dtype=np.float32)
        self.data_received.emit(np_data)
        self.buffer.clear()
```

#### 7.1.2 文件回放模式（File Replay Mode）

当选择文件回放模式时，系统使用 `FileReplayThread` 从本地 `.txt` 文件回放数据。该线程遍历指定文件夹下的所有 `.txt` 文件，按文件名排序后顺序回放，每 50 个数据点发射一次，并在每次发射后休眠 0.05 ms 以模拟实时数据流。

文件回放模式主要用于：
- 无硬件连接时的软件调试与功能验证
- 使用历史现场数据进行算法回溯测试
- 学术演示与教学场景

### 7.2 零污染虚拟串口硬件模拟器（mock_hardware.py）

#### 7.2.1 设计动机

在软件开发与调试阶段，通常面临以下困境：
- 真实硬件设备可能尚未就位或数量有限
- 现场数据采集受限于工况条件，无法随时获取
- 使用真实硬件进行反复测试存在设备损耗风险

为解决上述问题，系统提供了一个**零污染虚拟串口硬件模拟器** `mock_hardware.py`，它利用 macOS 内置的 **伪终端（Pseudo Terminal, pty）** 机制，在软件层面创建一个虚拟串口，完全模拟真实 STM32 硬件的行为。

#### 7.2.2 工作原理

```
[mock_hardware.py]                    [SandAlert PC]
      │                                     │
      │  pty.openpty()                       │
      │  master_fd ←→ slave_fd              │
      │       ↓                              │
      │  slave_name = /dev/ttys001           │
      │                                     │
      │  ── 打印虚拟串口名称 ──────────────→   │
      │                                     │
      │  ←── 用户按回车确认 ────────────────   │
      │                                     │
      │  ── 逐行发送数据 ─────────────────→   │
      │     os.write(master, f'{val}\n')     │
      │     每行一个浮点数，间隔 1ms           │
      │                                     │
      │  循环遍历所有 .txt 文件               │
```

核心代码逻辑：

```python
master, slave = pty.openpty()
slave_name = os.ttyname(slave)
# slave_name 如 "/dev/ttys001" 即为虚拟串口名称

# 逐行发送数据
for token in tokens:
    val = float(token)
    os.write(master, (f'{val}\n').encode('utf-8'))
    time.sleep(0.001)  # 1ms 间隔，模拟 1000 Hz 采样率
```

### 7.3 统一线程管理

`MainWindow` 通过 `active_thread` 属性统一管理当前活跃的通信线程：

```python
self.active_thread = None  # 初始无活跃线程

# 切换数据源时自动停止旧线程
def show_setup_dialog(self):
    dialog = SetupDialog(self)
    if dialog.exec():
        self.stop_active_thread()  # 停止旧线程
        if use_file_replay:
            self.active_thread = FileReplayThread(data_dir)
        else:
            self.active_thread = SerialReaderThread(port, baudrate)
        self.active_thread.data_received.connect(self.signal_tab.update_from_serial)
        self.active_thread.status_msg.connect(lambda msg: print(f"SYS MSG: {msg}"))
        self.active_thread.start()
```

`stop_active_thread()` 方法用于安全停止当前线程，在切换数据源或关闭窗口时调用：

```python
def stop_active_thread(self):
    if self.active_thread is not None and self.active_thread.isRunning():
        self.active_thread.stop()
        self.active_thread = None
```

这一设计确保了：
- **数据源切换安全**：用户切换串口或切换到文件回放模式时，旧线程被安全停止，不会残留后台进程。
- **资源释放**：串口文件描述符被正确关闭，避免端口占用。
- **统一管理**：所有通信线程的生命周期由 `active_thread` 单一入口管理，避免线程引用散落各处。

## 8. 安全关闭与线程生命周期管理

### 8.1 问题背景

在多线程 Qt 应用程序中，若用户在后台线程仍在运行时直接关闭主窗口，将导致以下严重问题：

1. 后台线程尝试向已销毁的 UI 对象发射 Qt 信号，触发底层 C++ 段错误（Segfault）。
2. 线程持有的文件描述符（如串口、文件句柄）无法被正确释放，造成资源泄漏。
3. 正在进行的 CSV 文件写入可能被截断，导致数据损坏。

### 8.2 解决方案：优雅关闭机制

系统在 `MainWindow` 中重写了 `closeEvent()` 方法，实现了两级安全关闭策略：

```python
def closeEvent(self, event):
    print("[Shutdown] 正在安全关闭所有后台线程...")

    # 1. 停止活跃的通信线程（串口或文件回放）
    self.stop_active_thread()

    # 2. 停止历史日志解析线程
    if hasattr(self.datalog_view, 'parser_thread') and self.datalog_view.parser_thread.isRunning():
        self.datalog_view.parser_thread.stop()
        if not self.datalog_view.parser_thread.wait(2000):
            print("[Shutdown] 警告：历史日志解析线程未能在 2 秒内退出")

    # 3. 接受关闭事件
    print("[Shutdown] 所有后台线程已安全终止，窗口即将关闭。")
    event.accept()
```

#### 8.2.1 停止标志位模式

`LogParserThread`、`SerialReaderThread` 和 `FileReplayThread` 均实现了 `_is_running` 标志位和 `stop()` 方法。在 `run()` 方法的循环中，每次迭代前检查该标志位：

```python
def run(self):
    self._is_running = True
    for i, file_path in enumerate(txt_files):
        if not self._is_running:  # 检查是否被要求停止
            break
        # ... 处理文件 ...
```

这种设计避免了使用 `terminate()` 强制终止线程可能导致的资源泄漏和死锁问题，确保了线程的优雅退出。

#### 8.2.2 超时保护

`wait(2000)` 设置了 2 秒的超时等待时间。若线程未能在 2 秒内正常退出，系统将打印警告信息并继续执行窗口销毁流程，防止应用程序无响应。

### 8.3 关闭时序图

```
用户点击窗口关闭按钮
    ↓
closeEvent() 被调用
    ↓
stop_active_thread() → 停止通信线程
    ├── SerialReaderThread.stop()
    │   ├── _is_running = False
    │   ├── serial_port.close()
    │   └── wait(2000)
    └── FileReplayThread.stop()
        ├── _is_running = False
        └── wait(2000)
    ↓
停止历史日志解析线程
    ├── LogParserThread.stop()
    │   └── _is_running = False
    └── wait(2000)
    ↓
event.accept() → 窗口安全销毁
```

### 9.2 工程总结

SandAlert PC 系统的核心算法设计遵循了以下工程原则：

1. **物理驱动**：所有信号处理步骤均有明确的物理背景，从传感器特性（-2.85 V 偏置）到声发射机理（砂粒撞击的宽频特性），再到能量-质量映射（动能定理），构成了完整的物理链。

2. **鲁棒性优先**：防翻车机制（滤波前禁止截断、寻峰后幅值限幅）体现了对工业现场恶劣电磁环境的深刻理解，确保了系统在非理想条件下的稳定运行。

3. **自适应性**：动态阈值机制使系统能够自动适应背景噪声水平的变化，在灵敏度和抗干扰之间取得动态平衡。

4. **可标定性**：通过现场标定实验确定转换系数 $K_{v^2}$，使系统能够适应不同管道工况，兼顾了通用性与个性化。

5. **工业兼容性**：三相分离器效率评估模型和 4-20 mA 模拟电流信号的引入，使系统能够无缝融入现有的工业 SCADA/DCS 体系。

6. **数据完整性**：CSV 工业报表录制与安全关闭机制共同保障了监测数据的持久化与完整性，满足工业审计要求。

7. **开发友好性**：双模通信架构（串口/文件回放）与零污染虚拟串口硬件模拟器的设计，使得系统在无硬件条件下即可完成完整的开发、调试与演示流程。
