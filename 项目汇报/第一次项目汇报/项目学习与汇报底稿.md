## 2. 当前项目定位

仓库 README 将项目定位为海上油气管道含砂监测的上位机与信号计算系统。学习时可把它拆为三项任务：

1. 从仪表或波形数据中获取含砂相关指标；
2. 对四通道波形估计声源方位；
3. 把采集、传输、计算、显示和记录连起来。

这三项任务的完成程度不能相互替代。通信成功不能证明质量估计准确；仿真方向估计成功不能证明现场撞击位置已被定位。

背景中的颗粒撞击、声传播、噪声来源与现场价值，后续需补充可核查的文献或仪表资料。当前依据项目定位组织问题，不写未经核实的行业数字。

## 3. 术语与容易混淆的量

| 术语 | 本项目中的解释 | 注意事项 |
|---|---|---|
| 上位机 / UI | 本机 Qt 操作界面 | 当前实际使用 PySide6；部分旧文档称 PyQt |
| Edge Service | 本机采集组织、网关和可靠上传服务 | 当前独立 Edge 的数据源是文件与模拟指标 |
| DSP | Digital Signal Processing，数字信号处理 | 当前用于波形滤波、阈值、寻峰和能量代理量 |
| IPS | 界面中标为 Impact rate 的指标 | DSP 实际返回窗口有效峰数；仪表模式直接读取寄存器，需分开解释 |
| Mass Rate | 界面标为 g/s 的砂质量流率 | 波形路径的单位与标定尚需核实；模拟仪表直接生成数值 |
| Cumulative Mass | 累计质量 | 本地 Modbus CSV 使用仪表累计读数的增量 |
| TDOA | Time Difference of Arrival，到达时间差 | 中间观测量，不等于空间坐标 |
| DOA | Direction of Arrival，到达方向 | 当前输出二维方位角，不是完整三维位置 |
| GCC-PHAT | 广义互相关及相位变换加权 | 用于估计通道间时差 |
| UCA | Uniform Circular Array，均匀圆阵 | 当前模型为四通道、四个正交方位 |
| ACK | 消息接收确认 | 与缓存清理和重传相关 |

## 4. 两条运行链路

### 4.1 本机仪表链路

```text
真实仪表或本机 Mock Modbus TCP
  → ModbusReaderThread 读取并解码寄存器
  → Qt 信号传递字典
  → UI 显示 IPS、砂率、累计量、电流和报警
  → CSV 记录
```

Mock 的默认地址为 127.0.0.1:5020，设备号 126，读取 Input Registers 0–10。客户端将砂率和电流的整数编码除以 100；累计量由两个 16 位寄存器合成。

这一链路传输的是指标，不含四通道原始波形，因此不能单独用于验证 DSP 或 TDOA。模拟器中的砂率和报警是为通信与界面检查生成的数据。

具体操作见 `SandAlert_PC_Replica/LOCAL_MODBUS_RUNBOOK.md`。本机解释器为 `/opt/miniconda3/envs/playground/bin/python`，UI 入口为 `SandAlert_PC_Replica/main.py`。

### 4.2 Edge 与计算服务器链路

```text
TXT/CSV 波形 → FileReplaySource → Edge
                                 ├→ 本机 WebSocket 网关 → UI 波形
                                 └→ 磁盘待发送缓存 → WebSocket → Server
                                                                    ├→ HDF5 波形
                                                                    ├→ SQLite 元数据
                                                                    └→ DSP / TDOA / 报警
                                                                         ↓
                                                                      结果回传
                                                                         ↓
                                                                      Edge → UI
```

Edge 还可同时生成 MockModbusSource 指标，经服务器存储和回传。它与文件波形是两个独立数据源，并不表示模拟指标由文件波形推算得到。

运行顺序为 Server → Edge → UI。默认服务端口为 8765，本机网关为 8766。远程部署须使用 `/home/lks/miniconda3/envs/core/bin/python`；本机使用 playground。

这些端口是项目约定；不能仅凭配置或文档认定服务当前正在运行。

## 5. 为什么采用这些模块

以下是根据模块职责整理的工程解释，不代表已经进行过技术选型对照实验。

| 选择 | 带来的作用 | 需要理解的代价或边界 |
|---|---|---|
| UI 与独立 Edge/Server 分工 | 显示、传输和计算职责清楚，可独立运行 | 引入连接状态、数据一致性与部署问题 |
| Qt 线程和信号 | 通信任务与界面更新分开 | 模式切换和线程退出需要正确处理 |
| WebSocket | 持续双向传送波形和结果 | 仍需自行设计认证、重连、确认和重发 |
| 磁盘 spool + ACK | 未确认数据可保留并重发 | 需要容量限制、去重与异常恢复；不能直接宣称任何故障下绝不丢失 |
| SQLite + HDF5 | 分别组织结构化记录与数组波形 | 跨文件一致性和备份需进一步考虑 |
| GCC-PHAT + 角度网格搜索 | 将时差观测与阵列几何联系起来 | 依赖通道同步、传播模型、声速和阵列参数 |

## 7. 已核对的方法概要，留待逐项推导

### DSP

`core/dsp_engine.py` 当前流程为：四阶 20 Hz 高通 → filtfilt → 绝对值整流 → 整流均值加阈值裕量 → find_peaks（至少相隔 10 个样点）→ 剔除幅值不小于 2.0 的候选峰 → 统计有效峰并计算峰高相对背景的平方和 → 除以转换系数。

其中“能量”是代码定义的峰高平方和代理量，未直接包含完整声学能量所需的物理单位和积分模型。2.0 的异常峰界限是实现中的经验阈值，不应据此断言所有更大信号必然来自插拔。

### TDOA

`core/tdoa_engine.py` 当前默认：四通道均匀圆阵，半径 0.05 m，声速 1500 m/s，采样率 2 MHz，角度步长 0.25°。采用 GCC-PHAT、物理时延约束、多峰候选、亚采样插值和角度代价搜索。频域限带默认关闭。

这些是算法模型参数，并非已确认的真实管道传感器布置、有效传播声速或现场精度。0.25° 是搜索网格间隔，不能直接作为角度测量准确度。

### 服务器触发

`server/processing.py` 使用 3000 样点滚动窗口；符合有效峰、窗口中部与事件间隔等条件后提取四通道 2000 样点切片进行方向计算。需要继续分析切片触发、重复事件抑制和窗口重叠如何影响统计。

## 8. 当前需要明确保留的问题

1. `ServerSettings.dsp_sample_rate` 默认 1000 Hz，而文件波形元数据默认 2 MHz；DSP 滤波与寻峰时间尺度需统一检查。
2. DSP 的 IPS 是窗口峰数，尚不能直接按“每秒撞击数”解释。滑动窗口重叠也可能造成事件重复计入。
3. 波形路径的质量流率、转换系数、窗口时长和累计积分需要一起核查，不能只改显示单位。
4. Edge 同时回传波形分析指标与模拟仪表指标，UI 共用显示字段，来源选择仍需明确。
5. analysis.result 与 tdoa.result 都可能触发 UI 方位结果记录，需核查重复事件。
6. UI 本地标定按钮尚无明确的服务器标定闭环。
7. 远程服务器当前状态未在本轮验证；真实 RTU、现场同步采集和现场精度均不能由本地测试代替。
8. 技术白皮书保留旧架构叙述；学习时以当前代码为实现依据。
